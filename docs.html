keybinds

  • Ctrl+T — new tab
  • Ctrl+W — close tab
  • Ctrl+L — focus the address bar
  • Ctrl+R — reload
  • Alt+W — close tab, but with more feeling

hawk://config

Hawk has a settings page that lives inside the browser itself, because a settings window is another thing in your way. Type hawk://config in the bar.

There you can toggle:

  • local — local SearXNG on/off
  • block3p — third-party cookie blocking
  • ualock — fixed user agent
  • blockmedia — camera & microphone off
  • dark — dark mode (also makes the web dark)
  • restore — restore last session on start
  • history — how many URLs it remembers (10–2000)
  • home — the home page URL

And two actions for when you decide you were never here:

  • action=clear_history — forget every URL (the file is wiped too)
  • action=clear_cookies — log out of everything, everywhere, at once

Every change saves to ~/.hawk/hawk.ini and applies to all open tabs immediately.

where your data lives

Everything is inside ~/.hawk. Back it up by copying that one folder.

  • ~/.hawk/hawk.ini — settings
  • ~/.hawk/history — URL memory (newest first, deduped, capped)
  • ~/.hawk/session — tabs open when you last closed it
  • ~/.hawk/cookies/cookies.sqlite — cookies, persistent, your logins survive restarts
  • ~/.hawk/searchd/src + ~/venv — the SearXNG checkout and its virtualenv
  • ~/.hawk/searchd/searchd.pid — the backend's pidfile. it's used properly now
  • ~/.hawk/searchd/searchd.log — backend whispers

the search backend, and why it dies on cue

Hawk boots a private SearXNG when the browser opens and kills it when the browser closes. There was a time when closing the browser left the engine running forever, because the pidfile recorded the wrong process — the kill signal went to a wrapper, and the wrapper went to heaven while the engine kept squatting on your machine. That is fixed:

  • the pidfile records the actual python process now
  • stop verifies the process died, escalates to kill -9, and sweeps for anything that slipped through the name searx.webapp
  • the browser installs a SIGTERM/SIGINT handler, so even "kill hawk" from a terminal takes the engine down with it
  • port 8080 and the loopback interface only — nowhere else on your network

If the engine can't start (first run, no network for the clone), Hawk falls back to DuckDuckGo HTML. It never opens at a tracking engine.

quirks (honest)

  • WebKitGTK cannot run Firefox / Mozilla add-ons. Engine limitation, not laziness. details in about →
  • the address bar uses the same box for URLs and searches. if it looks like a URL, it's a URL
  • the first launch is slow because it clones a search engine. subsequent launches are not
